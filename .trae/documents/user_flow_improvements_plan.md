# 用户流程优化计划

## 一、当前流程分析

### 学生流程

1. 注册 → 填写表单（姓名、邮箱、密码、学校、身份）
2. 登录 → 输入邮箱密码
3. 课程大纲 → 创建/编辑课程
4. 学习记录 → 记录学习行为
5. 回顾 → 查看学习分析
6. 通知 → 接受/拒绝老师邀请

### 老师流程

1. 注册 → 填写表单（姓名、邮箱、密码、身份=老师）
2. 登录 → 输入邮箱密码
3. 导师页面 → 查看学生、发送邀请、查看学生数据

### 当前痛点

| 阶段       | 问题                  | 影响                |
| -------- | ------------------- | ----------------- |
| **注册**   | 学校名称不统一，老师无法按学校筛选学生 | 老师看到所有学生，难以找到同校学生 |
| **注册后**  | 没有引导提示              | 用户不知道下一步该做什么      |
| **邀请系统** | 学生需要手动进入通知页面查看邀请    | 邀请容易被忽略           |
| **邀请系统** | 没有通知角标/计数器          | 无法知道有新邀请          |
| **学习记录** | 表单字段较多，录入繁琐         | 用户可能放弃记录          |
| **老师端**  | 学生列表不分学校            | 老师看到大量无关学生        |
| **回顾页面** | 只有历史数据，没有行动建议       | 用户不知道如何改进         |

## 二、优化方案

### 1. 注册流程优化

**目标**：让注册更流畅，确保数据一致性

**修改文件**：`src/pages/Signup.jsx`

**改进点**：

* 学校名称标准化：添加学校名称自动补全或常用学校列表

* 老师注册后直接进入导师页面，并显示引导提示

* 添加注册成功后的引导动画/提示

### 2. 通知系统改进

**目标**：让邀请更容易被发现和处理

**修改文件**：`src/pages/Notifications.jsx`, `src/components/Layout.jsx`, `src/index.css`

**改进点**：

* 添加通知角标（小红点）显示未读邀请数量

* 邀请到来时显示实时通知提示

* 优化通知页面布局，更突出待处理邀请

### 3. 老师端学生筛选优化

**目标**：让老师更容易找到目标学生

**修改文件**：`src/pages/Mentor.jsx`, `src/index.css`

**改进点**：

* 添加按学校筛选的下拉菜单

### 4. 学习记录流程简化

**目标**：让学习记录更快捷

**修改文件**：`src/pages/Learning.jsx`

**改进点**：

* 添加快速记录模板（常用课程+类别一键录入）

* 优化表单布局，减少操作步骤

* 添加快捷键支持（可选）

### 5. 回顾页面增强

**目标**：提供更有价值的学习洞察

**修改文件**：`src/pages/Review.jsx`

**改进点**：

* 添加学习建议/行动项

* 添加学习趋势预测

* 优化数据可视化

## 五、风险评估

| 风险      | 概率 | 影响      | 缓解措施      |
| ------- | -- | ------- | --------- |
| 通知系统复杂度 | 中  | 性能问题    | 使用轻量级实时订阅 |
| 学校名称匹配  | 低  | 筛选不准确   | 添加模糊匹配    |
| 数据迁移    | 低  | 历史数据不兼容 | 向后兼容设计    |

## 六、预期效果

* 学生邀请接受率提升（实时通知）

* 老师端操作效率提升（学校筛选）

* 用户留存率提升（引导提示）

* 学习记录频率提升（简化表单）
