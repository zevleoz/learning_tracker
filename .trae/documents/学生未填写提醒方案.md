# 导师端「连续两天未填写」提醒 — 实施方案

## Context

导师目前只能从「本周活跃」「最新提交」间接判断学生有没有在记录学习，无法一眼看出谁断更了。需要在学生管理页加一个小提醒：学生连续两天（昨天 + 今天）没有学习记录时，导师端给出轻量信号，便于及时跟进。

已确认口径（用户选择）：
1. **展示范围**：桌面端概览条新增「未填写」计数块 + 学生卡片状态行加琥珀色小点与「N 天未填写」文字。不加筛选 chip、不加顶部横幅。移动端做对应最小实现。
2. **判定口径**：按学习日判定（`learning_sessions.session_date`），昨天与今天都没有记录即提醒——与「本周活跃」同口径，无需解析提交时间，跨时区无风险。
3. **从未填写**：不提醒新账号；账号创建早于 7 天窗口、且窗口内无任何记录的学生显示「7 天以上未填写」（无法精确区分"从未填写的老账号"与"断更超 7 天"，为已知取舍）。
4. **约束**：不改数据库 schema / RPC，零新增请求——复用 `loadClassStats` 已有的批量查询；语义色只用于小色点，文字中性灰。

## 判定规则

以今天为 D0，窗口为 D-7 ~ D0（与现有查询一致）：

| 情况 | 结果 |
| --- | --- |
| 窗口内有记录，最后记录日 = D0 或 D-1 | 不提醒 |
| 最后记录日 = D-2 | 「2 天未填写」（天数 = D0 − 最后记录日） |
| 最后记录日 = D-7 | 「7 天未填写」（精确值，capped=false） |
| 窗口内无记录，`profiles.created_at` ≥ D-7 | 不提醒（新账号） |
| 窗口内无记录，`created_at` < D-7 或缺失 | 「7 天以上未填写」（capped=true） |

边界：`created_at` 恰为 D-7 视为新账号（不提醒，需在单测中固定）。

- `session_date` 先 `stripToDate` 再比较；定宽 `YYYY-MM-DD` 字符串比较即日期比较。

## 不做的事

- 不加「未填写」筛选 chip、不加顶部提醒横幅。
- 不改数据库 schema / RPC；不新增网络请求。
- 不做 focus/visibilitychange 时的 classStats 刷新（天粒度收益小，跨天陈旧成本最低的替代方案：在切回 students 视图且距上次加载超过一天时惰性重载，留待后续）。
